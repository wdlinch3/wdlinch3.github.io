# Packet learning objectives

The canonical wording remains in `support-files/aa@tj_general_info/vlo/vlo_aa_{ss,x}.qmd` in the umbrella workspace. Do not edit `_data/aa_objectives.json` by hand.

Rebuild after an approved wording change:

```sh
python3 scripts/build_packet_objectives.py --workspace-root /Users/wdlinch3/Documents/github
bundle exec jekyll build
```

`_data/aa_packet_objectives.yml` selects stable objective codes/prefixes for each published packet; it contains no duplicate objective wording. `_data/aa_courses.yml` associates each class card or part with its packet ID. The importer validates references, preserves the canonical wording, records source hashes, and generates the shared catalog and small page entry files. Complete SS/X pages contain every objective row in those sources, including later course topics. Packet pages do not imply a test scope or add new assessment objectives.

Packet mappings use the current packet topics and retain broad objectives where a packet develops only part of them. In particular, the combinations objectives span several astrodynamics packets. Geometry, units, and light-travel objectives recur where applied. Celestial Navigation I covers terrestrial/horizontal coordinates and observation; II covers equatorial coordinates, solar motion, charts and planispheres. Broader eclipse and precession objectives remain in the complete course list. Kepler I selects ellipse/conic geometry; second-law applications appear with Astrodynamics III.

The new HTML collection is at `/aa/objectives/`. Historical `/aa/vlo/` HTML/PDF routes remain available; their older PDFs are not regenerated by this HTML-only task. No private notebooks or assessment files are published by this generator.

Refresh HTML with the installed Ruby 3.3.4 runtime:

```sh
AA_WORKSPACE_ROOT=/Users/wdlinch3/Documents/github ruby scripts/render_aa_vlos.rb --html-only
python3 scripts/build_class_objective_tables.py
```

The second command copies the complete rendered document body into generated includes; do not edit those includes directly. It preserves every table row, heading, and scope note. `_data/aa_vlos.yml` owns both routes. Director builds with `_config.yml,_config.school.yml`; objective pages then use the shared class shell. Personal rendering remains unchanged. The HTML-only option leaves existing PDFs untouched.
